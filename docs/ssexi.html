ssexi connects fixi to Server-Sent Events. The server pushes named events, your HTML listens, fixi swaps. Live notifications, progress, chat, dashboards in 1.4KB.

★ Anatomy

Plain HTML,
real-time everything.

Open an SSE connection by URL, then trigger fixi swaps on each named event. Live UIs without a websocket framework.

The HTML

<!-- subscribe to /stream, swap on each "msg" event -->
<div
  sse-connect="/stream"
  fx-trigger="sse:msg"
  fx-swap="beforeend"
  fx-target="#feed"></div>

<ul id="feed"></ul>

The Result

Each event: msg from the server gets appended to the feed. No polling. No websocket framework.

    ★ Attributes

    Subscribe with one
    attribute.

    sse-connectURL of the SSE endpoint to subscribe to
    sse-closeEvent name that closes the connection
    fx-trigger="sse:<evt>"Trigger fixi swap when named event arrives
    fx-swapStandard fixi swap modes work (beforeend, paxi, ...)
    reconnectAutomatic with backoff if connection drops
    cost1.4KB brotli, only loads if you use it
    ★ Live wire

    Each event,
    a swap in your DOM.

    Server names the event, your HTML decides what to do with it. Here's a typical chat connection.

    12:04:01 connection opened — sse-connect="/chat"
    12:04:03 event msg → swapped into #feed
    12:04:08 event typing → toggled .is-typing
    12:04:12 event msg → swapped into #feed
    12:04:30 connection dropped → auto-reconnecting…
    The server has something to say. Your HTML is listening.
